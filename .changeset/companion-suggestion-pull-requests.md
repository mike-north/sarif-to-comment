"sarif-to-comment": minor
---

Offer whole-file proposals, grouped changes and fixes with several changes as companion suggestion pull requests. When a proposal's delivery list names `companion` (for example `--file-operations companion`, `--grouped-edits companion` or `--delivery companion`; see the delivery policy entry), each distinct file creation or deletion, each group of results sharing a `properties.sarifToComment.suggestionGroup` value, and each fix with several changes is proposed as a pull request into the reviewed pull request's head branch: one commit on the reviewed commit, an ordinary reference to the original (never a closing keyword), a hidden structured marker, and the repository's existing suggestion label. The review links each one, and the published outcome lists them in `suggestions`. Before anything is written, the tool checks the group rules, conflicts between proposals, a limit of 10 suggestion pull requests, that the account can push and that the labels exist; a pull request from a fork or into another base, where none can be made, sends each proposal to the next mechanism of its list, or blocks. `validate` reports the same outcome. Each branch, pull request and label is recorded beside the state file before it is sent and never sent twice; a retry finds a lost pull request by its branch and marker, continues the steps never sent, and never repairs what a person changed. The default delivery lists never name `companion`.
