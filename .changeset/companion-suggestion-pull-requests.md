"sarif-to-comment": minor
---

Offer whole-file proposals and explicitly grouped changes as companion suggestion pull requests. With `options.suggestionPullRequests: true` (`--suggestion-prs` on `publish` and `validate`), each distinct file creation or deletion, and each group of results sharing a `properties.sarifToComment.acceptanceGroup` value, is proposed as a draft pull request into the reviewed pull request's head branch: one commit on the reviewed commit, an ordinary reference to the original (never a closing keyword), a hidden structured marker, and an existing label (`suggestion`, or `suggestionLabel` / `--suggestion-label`). The review links each one, and the published outcome lists them in `suggestions`. Small edits stay native suggestions. Before anything is written, the tool checks the group rules, conflicts between suggestions, a limit of 10 suggestion pull requests, and that the head branch is in the same repository and not the default branch, that the reviewed commit is the head, that the account can push and that the label exists; `validate` reports the same outcome. Each branch, pull request and label is recorded beside the state file before it is sent and never sent twice; a retry finds a lost pull request by its branch and marker, continues the steps never sent, and never repairs what a person changed. The setting is off by default: without it, requests, reviews and state files are unchanged, and a grouped document is refused, naming the setting.
