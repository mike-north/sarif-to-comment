Close companion suggestion pull requests whose original pull request has ended. `closeSuggestionPullRequests` in the library and `sarif-to-comment close-suggestion-prs --repo OWNER/REPO` in the CLI close the suggestion pull requests that are still open once their original has merged or closed. `dryRun` / `--dry-run` reads and verifies everything and closes nothing.

- **Discovery by branch.** By default, cleanup lists the repository's `suggestion-pr/` branches with their open pull requests, in one paginated GraphQL query, so its cost grows with suggestion branches, not with the size of the repository. Each pull request found must carry the repository's suggestion label (`suggestion-pr`, or the `label` of `.github/suggestion-prs.json` on the default branch; an invalid file stops cleanup before anything is closed). `label` / `--label NAME` checks the open pull requests carrying that label instead, for suggestions left under a previously configured label, and does not read the repository configuration. `originalPullNumber` / `--original N` checks only the pull requests that reference that original.
- **Whose suggestions.** `owner` / `--owner me|all` is about who opened the suggestion pull request, not the original. The default, `me`, closes only those opened by the token's account; `all` closes any conforming suggestion pull request.
- **Bounded.** A sweep counts its candidates (suggestion branches, or pull requests with the label) in its first request. A `--label` sweep whose first 20 pull requests show no suggestion marker and no `suggestion-pr/` branch stops first, with the status and warning `label-not-suggestion-prs` (exit 2), judged from the listing alone and however many pull requests carry the label; `force` / `--force` checks them anyway. Then, over `maxCandidates` / `--max-candidates N` (default 500), nothing is checked, `--force` or not: the status is `too-many-candidates` (exit 1) with a `suggestion-pr-candidates-over-limit` error stating the count, the limit and how to narrow the run or raise the limit. A mistyped or overly broad label costs one request. The default sweep's count includes the branches of suggestions already closed, since cleanup never deletes a branch, so an active repository can reach the limit over time; raise it with `--max-candidates N`.
- **No ignored options.** `force` / `--force` without a label or with an original, and `maxCandidates` / `--max-candidates` with an original, would change nothing, so they are refused (library: `TypeError`; CLI: usage error, exit 1) before any request.
- **Strict verification.** A pull request counts as a suggestion only when its description carries the hidden suggestion marker exactly in its canonical form and it comes from its own `suggestion-pr/` branch in the same repository; titles are never read. It is closed only after its original has been read and found merged or closed, and after the suggestion has been read again and verified (still open, same marker and label, its own branch). An original that can't be read is reported `unverified` and never treated as ended. Everything is read before the first close.
- **Closing only.** Closing is the only change: branches are never deleted and nothing else is edited. Running it again is safe.
- **Results.** Each pull request gets a result: `closed`, `would-close`, `already-closed`, `left-open`, `unverified`, `permission-limited` (GitHub refused the close with 403 or 404), `failed`, `not-conforming`, `other-owner` (someone else opened it) or `unlabeled`. The outcome and the JSON document report the `owner` scope and `counts` (`candidates`, `checked`, `labeled`, `conforming`). The run is `complete` (exit 0), `permission-limited` (exit 2: refused closes are reported apart from failures), `incomplete` (exit 3: safe to run again), or one of the two stopped statuses above.

Suggestion labels containing a comma are refused, since GitHub's label filter would read them as several labels.
