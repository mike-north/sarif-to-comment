**Close suggestion pull requests whose original has ended.** The new `sarif-to-comment close-suggestion-prs --repo OWNER/REPO` command and `closeSuggestionPullRequests` library function close the suggestion pull requests that are still open once their original pull request has merged or closed. They act on any suggestion pull request that follows the convention, whichever tool created it. `--dry-run` (`dryRun`) reads and verifies everything and closes nothing.

- **Discovery.** By default, cleanup lists the repository's `suggestion-pr/` branches with their open pull requests in one paginated query, so its cost grows with suggestion branches, not with the size of the repository. Each pull request found must carry the repository's suggestion label (`suggestion-pr`, or the label in `.github/suggestion-prs.json` on the default branch; an invalid file stops cleanup before anything is closed). `--label NAME` (`label`) checks the open pull requests carrying that label instead, for suggestions left under a previously configured label. `--original N` (`originalPullNumber`) checks only the pull requests that reference that original.
- **Whose suggestions.** `--owner me|all` (`owner`) is about who opened the suggestion pull request. The default, `me`, closes only those the token's account opened; others are reported as `other-owner` and left open.
- **Bounded.** A sweep counts its candidates in its first request. A `--label` sweep whose first 20 pull requests show no suggestion marker and no `suggestion-pr/` branch stops there, with the status and warning `label-not-suggestion-prs` (exit status 2); `--force` (`force`) checks them anyway. Over `--max-candidates N` (`maxCandidates`, default 500), nothing is checked: the status is `too-many-candidates` (exit status 1). A mistyped or overly broad label costs one request. The count includes the branches of suggestions already closed, since cleanup never deletes a branch, so an active repository can reach the limit over time; raise it with `--max-candidates`. `--force` without `--label`, and `--max-candidates` with `--original`, are usage errors (a `TypeError` in the library).
- **Strict verification.** A pull request counts as a suggestion only when its description carries the suggestion marker in its canonical form and it comes from its own `suggestion-pr/` branch in the same repository; titles are never read. It is closed only after its original has been read and found merged or closed, and after the suggestion has been read again and verified. An original that cannot be read is reported `unverified` and never treated as ended. An original that does not exist (GitHub answers 404 once the repository is known to exist) is `not-found`: with `--original`, cleanup is then `complete` with an `original-pull-request-not-found` warning, and in a sweep the suggestion naming it is `not-conforming`. Everything is read before the first close.
- **Closing only.** Closing is the only change: branches are never deleted and nothing else is edited. Running it again is safe.
- **Results.** Each pull request gets a result: `closed`, `would-close`, `already-closed`, `left-open`, `unverified`, `permission-limited` (GitHub refused the close with 403 or 404), `failed`, `not-conforming`, `other-owner` or `unlabeled`. The outcome reports the `owner` scope and `counts`. The run is `complete` (exit status 0), `permission-limited` (exit status 2), `incomplete` (exit status 3: safe to run again), or one of the two stopped statuses above.

Suggestion labels containing a comma are refused, since GitHub's label filter would read them as several labels.
