Publish proposed file creations and deletions. A finding carrying a whole-file proposal (as `add-staged-changes` writes it) no longer blocks `publish` and `validate`: each distinct proposal becomes one section of the review body, followed by every finding that carries it with its own attribution. A new file is shown in full in a code block whose fence can't be closed by its content, with its size, line endings, final newline, byte-order mark and mode stated, so an empty file stays distinct from one holding a newline. A deletion links the file at the reviewed commit and states that the whole file is removed, not emptied; its content is never read, so binary files and files over the 1,000,000-byte source limit can be deleted. Content a code block can't show exactly (control characters, a bare carriage return, mixed line endings, invisible bidirectional or separator characters, binary or non-UTF-8 contents), a creation over an existing file, a deletion of a missing one, and conflicting proposals still block the whole review before anything is written. Nothing is truncated or split. The staged-changes receipt no longer warns that the publisher refuses these proposals.
