**Producer Markdown is read as CommonMark before it is trusted.** A SARIF message's Markdown is now parsed with micromark and its GFM extension (the parser remark uses; `mdast-util-from-markdown`, `mdast-util-gfm` and `micromark-extension-gfm` are new runtime dependencies, loaded with `import()`), instead of a hand-written reading. Code spans, fences, HTML blocks, list items and block quotes are therefore exactly what CommonMark says, and raw HTML is checked for balance only where the parser finds raw HTML. Markdown that would swallow or hide what follows it was published by 0.2.1, and GitHub then rendered the attribution, later findings and the native suggestion block inside it. That Markdown is now refused as `producer-html-unbalanced` or `producer-fence-unclosed`. It includes a fence or `<details>` inside an HTML block, an HTML comment block left open, a code span that only seemed to hide a tag, a closing fence indented four spaces, and a fence after a block quote's fence. Markdown CommonMark reads as harmless is no longer refused. Examples are a code span whose second line starts with `<`, an HTML block holding a fence line, and an unterminated `<!--` or tag inside a paragraph, which is text. An HTML comment that GitHub's older comment rules might not read as one (`<!-->`, or `--` inside) is read both ways, so a tag it seems to enclose, opening or closing, counts under either reading. A trailing `/>` closes only void elements, so `<details/>` is an open element and is refused. Markdown placed after a label on the same line (a location message, a fix description, an alternative's description) is also checked as composed: `    <details>` or a fenced `<details>` is harmless at the start of a line but leaves the element open after `**Fix:** `. As a backstop, every inline comment, every suggestion pull request's description and the review body are checked again once fully composed and within their limits: nothing open, exactly the native suggestion block the core built, and the marker last. A value shown as a code span, such as a rule id containing line breaks, now renders the breaks as spaces instead of breaking out of its paragraph.
