Publish findings that offer alternative fixes instead of refusing the whole review. When a SARIF result carries several fixes, its first fix is the suggested change, presented exactly as a single fix is (a native suggestion, or its group's suggestion pull request); the producer's order decides and the tool never picks a different one. Every further fix is listed in the same comment under **Alternatives to consider:** as `(1)`, `(2)`, … with its description and the reviewed lines it would replace, in a code block whose fence is longer than any backtick run inside it, naming its file when that differs from the first fix's. Alternatives are never applied, merged into one patch or grouped. They count toward the size limits, so an oversized comment still refuses the whole review and nothing is truncated. An alternative that is not one text replacement in one file applying exactly to the reviewed commit, or whose lines a code block can't show exactly, refuses the review at its own pointer (`/runs/0/results/0/fixes/1`); `publish` and `validate` agree, and `inspect` lists every fix. The diagnostics for a fix that changes several files or makes several replacements now explain that it is one change applied together.
