Publish findings that offer alternative fixes instead of refusing the whole review. When a SARIF result carries several fixes, its first fix is the suggested change, presented exactly as a single fix is (a native suggestion, its group's suggestion pull request, or, for a fix with several changes, its own suggestion pull request); the producer's order decides and the tool never picks a different one. Every further fix is listed in the same comment under **Alternatives to consider:** as `(1)`, `(2)`, … with its description and the reviewed lines it would replace, in a code block whose fence is longer than any backtick run inside it, naming its file when that differs from the first fix's. An alternative changing several files or making several replacements is read as a fix with several changes is (replacements on the same lines form one change) and listed with one labelled part per change, and a CRLF replacement is shown with LF line breaks and "(CRLF line endings)" stated beside it. Alternatives are never applied, merged into one patch or grouped. They count toward the size limits, so an oversized comment still refuses the whole review and nothing is truncated. An alternative whose replacements don't apply exactly to the reviewed commit, overlap, or can't be shown exactly (binary content, invisible or bidirectional characters, a carriage return inside a line, mixed line endings) refuses the review at its own pointer (`/runs/0/results/0/fixes/1`); `publish` and `validate` agree, and `inspect` lists every fix.
