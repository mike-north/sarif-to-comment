Two substantive acceptance findings are closed:

- Building before checking regenerated committed API/reference output and masked stale committed files. Both CI and publish now check scoped Git status after the build. The verifier exercised clean, modified, deleted and newly generated/untracked output cases, plus an unrelated untracked file: drift is refused and unrelated files are ignored. Publish preflight conditions and ordering remain intact.
- The publication-state predicate originally claimed a string-only phase despite accepting historical array-valued phases. The repaired parsed-state type includes the exact nested one-element array forms and keeps their unvalidated receipt/refusal payloads `unknown`. Strict string comparisons alone select validated receipt/refusal branches. Thirty-six behavior tests were committed before the repair, passed against 0.2.0, and rejected a deliberately tightened parser. Compile controls reject the old type and false optional typed payloads. Fable 5.1 independently compared 528 state scenarios with zero differences and closed the blocker; its additional type-test coverage finding was repaired. The verifier also compiled a separate boundary probe against the generated private declarations.

The final AST inventory covers 60 owned TypeScript files and finds zero non-const casts, angle assertions, non-null assertions or explicit `any` keywords. Strict compiler settings remain enabled without `skipLibCheck`. Runtime suppressions remain narrow and documented; new `@ts-expect-error` lines are negative compile controls. Remaining tracked JavaScript is the justified ESLint configuration and historical evidence/data, not owned runtime, tests or build/release tooling. Public declarations remain generated, Node-type-free and unchanged by the state repair; its internal type export does not enter the public rollup.
