# TypeScript migration work record

> **Historical work record (reconciled September 28, 2026).** The migration was released as 0.2.1. For current status, see [Current status and reconciliation](status.md).

The user asked for the repository to be converted to strict TypeScript. This changed the implementation language of the released 0.2.0 behavior. It was not a new product milestone, and it did not extend the deferred feature set. The record was condensed on September 28, 2026 to durable facts. The narrative of how work was assigned, run and supervised is preserved in Git history.

**Baseline.** Repository commit `2829530de8ebeee1a0c144307a3d964ab716a454`, release commit `da3c138897d45deaf90817bf10afbb426717cda5`, npm `sarif-to-comment@0.2.0`. The accepted baseline passed:

- 1,806 tests in 138 suites;
- Node 22 and 24 CI;
- installed public-interface acceptance;
- live GitHub source and fix fidelity checks.

See [second-milestone-release-verification.md](second-milestone-release-verification.md). A registry 0.2.0 consumer was kept and checked against all 246 accepted file hashes, for later differential comparison.

## Scope and constraints

The scope covered the owned runtime, CLI, tests and helpers, and build and release tooling. Generated JavaScript, data, vendored material and justified minimal configuration glue are outside it. The migration had these constraints:

- Strict TypeScript must provide meaningful types and generated declarations.
- Runtime input validation and existing behavioral contracts must not be weakened.
- Tests come first, and intent comments must be durable.

Remote Git and npm actions were covered by the user's standing authority for pushes to the default branch and for patch or minor releases below 1.0.0 through the existing guarded workflow.

## Plan and review

The plan is [typescript-migration-plan.md](typescript-migration-plan.md). It was built from read-only surveys of runtime typing, packaging and release tooling, and test and documentation contracts. An independent critique identified these hazards before any conversion:

- `__esModule` interop changes;
- changes to Error own properties;
- optional-property and key-order changes;
- dependency tests that pass vacuously once the compiler reprints the code;
- intermediate declaration files entering the npm tarball;
- Node types leaking into public declarations.

The plan was revised to address them. It preserves the private runtime seams through public overloads, and it drops the false assumption that `allowJs` copies JavaScript unchanged.

Plan approval came with these corrections:

- keep the runtime hooks;
- defer optional helper consolidation;
- run targeted checks per module and the assembled suite at integration points;
- keep the native-TypeScript development floor separate from supported consumers;
- detect stale output reliably when inputs are added or removed;
- keep migration worktrees apart from unrelated local scaffolding.

## Execution

- **Toolchain spike.** This confirmed native `.mts` execution on Node 22.18 and later, API Extractor handling, and strict dependency type checks with no `skipLibCheck`.
- **Characterization tests.** These were added before any change (commit `5086ab2`): 1,830 tests in 144 suites, all passing on the unchanged JavaScript, with intentional behavior mutations that make them fail.
- **Build infrastructure.**
  - 19 target-layout assertions failed before the implementation.
  - The implementation added the build layout, strict configurations, a freshness manifest and guard, relocated test imports, and release and documentation integration.
  - 1,873 tests then passed on Node 24.14.0, 22.23.3 and 22.18.0.
- **Runtime conversion in three integration batches.**
  - The first seven modules were converted with implicit interop explicitly disabled, and no `__importStar` helper remained.
  - Authoring, inspection, staged extraction and review preparation followed, with 23 comparison cases showing no difference from the original JavaScript.
  - Last came the public boundary: the entry point, CLI and executable, with declarations generated by API Extractor and the handwritten declarations removed.
  - The combined 1,873-test gate passed after each batch.
- **Interrupted mutation.** An observation timeout ended one execution run while a test mutation was still in flight. It left `Object.freeze` removed from `src/staged-git.cjs`. The file was restored, and its identity was verified against the baseline before work resumed.
- **Capacity limit.** A provider capacity limit paused the work once. Completed work was preserved, and runtime identity to the baseline was re-verified before resuming.
- **Fixture and test conversion.**
  - Eleven fixture modules were converted.
  - A test oracle captured all 1,873 original test names and assertion information across 24 files. It detects renamed, skipped, dropped and weakened checks.
  - The converted suite reached 1,879 passing tests.

## Independent review and acceptance repairs

- **Freshness check.** An independent review found that building before checking regenerated the committed API report and documentation, so the freshness gate could never fail. The repair checks scoped Git status after the build. A follow-up covered untracked generated files. The final gate was exercised against clean, changed, deleted, newly generated or untracked, and unrelated-file cases.
- **Unsound type predicate.** Independent verification found that the publication-state predicate promised a string-only `phase`, although the historical parser accepts array-valued phases. Preserving runtime behavior does not justify an unsound predicate. The repair keeps historical parsing and describes the accepted state honestly. Details and results:
  - 36 behavior tests were committed before the repair.
  - A 528-scenario comparison against 0.2.0 found zero differences.
  - Compile controls reject the old type.
- **Installed acceptance.** An independent verifier packed and installed the source into a disposable consumer. The unchanged library, CLI and insertion acceptance oracles passed.

## Retrospective

The implementation's retrospective acknowledged four mistakes:

- the unsound predicate;
- the build-masked freshness check;
- the in-place mutation that was interrupted;
- a lifecycle mistake with background tasks.

It drew these lessons:

- Type predicates must describe every accepted value truthfully.
- Run mutation controls on disposable copies.
- Check changed, deleted and untracked generated output.
- Keep handbacks concise, with pointers to evidence.

No global guidance changes or history rewrites were adopted at the time. Optional follow-up proposals, such as helper consolidation and narrowing the private seams, are triaged in [#12](https://github.com/mike-north/sarif-to-comment/issues/12).
